# Roadmap: Local HTML Artifacts

## Goal

Make sshler the one-stop catalog for HTML generated by people, scripts, and coding agents. A registration points at an existing file or directory; sshler stores organization metadata, discovers pages, and provides a loopback-only viewing origin. Unregistering never deletes source files.

## Delivered foundation

- [x] Required top-level projects with rename and cascade-unregister controls
- [x] Arbitrarily nested slash-delimited group paths
- [x] Three registration modes:
  - `file` exposes one exact HTML file
  - `site` exposes a directory through one entry point
  - `collection` recursively discovers HTML pages
- [x] Idempotent registration by canonical source path
- [x] REST API and `sshler artifact` CLI for add/find/list/show/update/rescan/open/remove
- [x] Search and filters across metadata and discovered page titles
- [x] Stable project/artifact aliases plus optional root-relative URL mounts
- [x] Vue catalog with project sections, nested groups, whole-row page toggles, edit and trash actions
- [x] Sandboxed inline preview and separate-tab opening
- [x] A separate loopback-only static server with no CORS permission
- [x] Traversal, hidden-path, symlink-escape, sibling-file, and page-count protections
- [x] English and Japanese UI text
- [x] Agent skill for create-then-register workflows

## Architecture

The main FastAPI application remains the catalog and control plane. Its lifespan starts a separate `ThreadingHTTPServer` on `127.0.0.1`; the selected port is reported by the authenticated bootstrap payload. Browser code constructs viewing URLs only when the UI itself is reached through `localhost`, `127.0.0.1`, or `::1`.

Registrations live in the existing SQLite state database:

- `ArtifactProject`: stable ID and URL slug, display name, normalized unique name, timestamps
- `ArtifactRegistration`: project, stable URL slug, optional global mount, group, canonical source
  path, mode, optional entry point/title, timestamps

The database contains pointers and presentation metadata only. Source bytes remain owned by the filesystem.

## Security invariants

- Bind the content server to IPv4 loopback only.
- Do not add CORS headers.
- Serve only `GET` and `HEAD`; reject mutation methods.
- Reject traversal, hidden components, NULs, backslashes, non-regular files, and resolved paths outside the registration root.
- In `file` mode, never expose siblings.
- Ignore hidden and symlinked directories during collection discovery.
- Cap collection discovery at 1,000 HTML pages and title reads at 256 KiB.
- Send `no-store`, `nosniff`, `no-referrer`, and cross-origin opener isolation headers.
- Keep unregister and project cascade operations metadata-only.
